# 代码质量与安全检查：原理与对比

**简体中文** | [English](2026-09-18-review.en.md)

首次整理：2026-09-18；各案例来源复查时间见详情。验证状态：**未复现**。

## 选择建议

PR 评审可对照 14 项检查、jev-review 和 jev-rabbit：分别重在明确风险与升级、迭代评分、自然语言团队规则。代码库分类器关注整体结构。命令安全、越狱预筛和上传判断对应不同防线，应分别评估漏报。 ESLint 规则实验判断小代码片段是否合规；OpenCode 权限插件在工具运行前决定放行、询问或拒绝。两者分别检查代码与操作，不能互相替代。 注释评分把准确性和实用性拆开，解释性强于单一总分，但目前只有两个简单样例；ESLint 实验按规则检查片段，PR 工具覆盖更广的改动。三者应按任务范围和证据规模比较。 Script.it 先给 diff 评分、命中后再写解释，减少长流程开销，但作者仅召回 75% 已确认 bug。与探索型评审相比，应把少误报和多漏报同时列出。

## 同类逐项对比

以下优势和限制是基于作者公开说明的技术分析；不构成同条件实验结论。

| 案例 | 相对优势 / 适用场景 | 限制 / 尚缺证据 |
| --- | --- | --- |
| [jev-review MCP](../cases/2026-09-18-jev-review/README.md) | 质量反馈可以嵌进开发循环，适合观察修改前后变化。 | 实验性插件；优化评分可能迎合评审指标，不能替代测试和人工审查。 |
| [14 项 PR 风险检查](../cases/2026-09-18-typed-pr-review/README.md) | 检查项和升级规则明确，比单个“代码好不好”评分更易检查。 | 只展示 6 个 PR；语义风险分类不等于漏洞检测已充分覆盖。 |
| [jev-rabbit 自然语言规则](../cases/2026-09-18-jev-rabbit/README.md) | 适合补充类型检查或 lint 难以表达的团队语义约定。 | 发帖时仍称即将公开，发布状态未确认；规则含糊会导致审查不一致。 |
| [代码库复杂度分类器](../cases/2026-09-18-codebase-classifier/README.md) | 评估对象是代码结构，可与逐行 PR 检查互补。 | “过度设计”依赖项目背景；没有证明分类结果能指导安全重构。 |
| [fx auto mode 命令安全分类](../cases/2026-09-18-fx-safety/README.md) | 对应具体的代理执行门槛，适合研究低延迟预筛。 | 原帖没有完整测试集；安全决策不能仅按平均准确率自动放行。 |
| [越狱提示预筛](../cases/2026-09-18-jailbreak-screen/README.md) | 适合把便宜的分类作为安全流程前置步骤。 | 作者明确是早期尝试；“接近 100%”是期望，不是已有结果。 |
| [资料上传判断器](../cases/2026-09-18-upload-check/README.md) | 把判断放在具体业务动作前，可研究敏感内容预筛交互。 | 演示不足以证明能识别所有敏感信息；不能替代组织权限策略。 |
| [按 ESLint 规则说明判断代码](../cases/2026-09-18-eslint-rule-judgments/README.md) | 适合探索自然语言规则能否转成快速代码判断；比通用 PR 打分更聚焦单条规则，可与确定性 lint 结果对照。 | 约九成正确来自作者的小片段实验，不是整个仓库或真实 PR 的可靠性；仍需公开样本、独立测试与各类误报漏报。不具备确定性 lint 的保证。 |
| [OpenCode · 意图感知权限插件](../cases/2026-09-18-opencode-intent-permissions/README.md) | 能对 shell、webfetch 等不同工具表达相同的语义限制，减少逐条穷举命令；与命令危险性评分相比，进一步接入权限决策。 | 视频中的拦截不证明无法绕过；应保留确定性硬边界。0.1.0 明确不支持 Code Mode execute，策略、近期用户消息及工具输入会送至 TypeSafe；本库未执行攻击或权限测试。 |
| [代码注释 · 准确性与实用性评分](../cases/2026-09-18-code-comment-scoring/README.md) | 把事实正确与信息价值拆开，比单一代码总分更容易看出问题；与 ESLint 规则实验同属局部代码判断，但这里评的是注释质量，不是规则是否合规。 | 只有两个简单样例，不能证明复杂代码的判断效果；评分不是独立测试准确率，也没有自动删除或改写注释的证据。作者把它定位为可能减少大模型复核次数的初筛，而非完整审查方案。 |
| [Script.it · 先筛问题再写评审](../cases/2026-09-19-script-code-review/README.md) | 与整段代理式评审相比，更明确地把发现问题与文字说明分开；作者同时披露了召回损失。 | 私有测试集规模和标注未公开；“零误报”只指该批开发者曾反驳的问题，不能推广为生产环境永不误报。 |

## 可观察流程与机制

代码或待执行内容 + 明确规则 → 多个窄判断 → 程序合并结果 → 提示、拦截或转交复核。

14 项 PR 检查公开了概率区间升级策略，是比单一总分更可检查的设计。jev-review 的评分可用于反馈，但高分不等于测试通过。安全预筛的低费用不能替代错误代价评估。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。

## 复现实验建议

按风险分别统计误报和漏报，保留独立标注样本；测试信息不足、输入含恶意指令、规则冲突和不确定结果。复现时保留人工评审与静态工具对照。
