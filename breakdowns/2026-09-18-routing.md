# 模型、技能与工具路由：原理与对比

**简体中文** | [English](2026-09-18-routing.en.md)

首次整理：2026-09-18；各案例来源复查时间见详情。验证状态：**未复现**。

## 选择建议

模型选择看 Eve 与 Ephraim 的演示；已有代理编排可以看 Firstmate 和本地分工。技能库检索看 Skillbox；想连接日常工具看 Coding Garden；Eve 工具代理展示局部替换；ai-cli 是统一接入入口。这些方案可以组合，并非互相替代。 Hono JevRouter 选择 HTTP 处理函数，规则用自然语言表达，且按注册顺序取首个达标路由；与选择模型或技能不同，分流错误直接改变响应内容，不能用来代替认证。 Codex Model Router 逐轮选择模型和推理配置，公开回退策略，但用户已观察到简单任务过度选强模型；应对比任务质量、缓存和整体账单，而非只看分类速度。 Claude Code Mod 默认路由子代理和主会话推理力度，关闭主模型切换；相对 Codex 的逐轮模型路由，更应分别检查缓存、回退与最终任务质量。 Astra-Ares 在同一模型的生成步骤之间调推理强度，OpenClaw 提供插件共用的决策接口；前者要比较任务质量、总费和缓存命中，后者要区分开发接口与尚未落地的用途。 工作流编辑器把判断节点连起来，AgentRun 从重复任务形成流程，Monid 接工具处理；不要把三者都理解成换模型。Prompt Box 增加机器/目录选择，Corent 强调按工作量设阈值：分别测误分派和回退质量。

## 同类逐项对比

以下优势和限制是基于作者公开说明的技术分析；不构成同条件实验结论。

| 案例 | 相对优势 / 适用场景 | 限制 / 尚缺证据 |
| --- | --- | --- |
| [Eve 条件式模型路由](../cases/2026-09-18-eve-router/README.md) | 选择标准显式化，适合作为独立路由层。 | 原帖未给路由准确率、配额策略或失败回退；只核验到演示截图。 |
| [请求到模型路由器](../cases/2026-09-18-ephraim-router/README.md) | 演示包括选模型后的实际调用，比只展示分类更完整。 | 没有公开统一任务集，不能证明总成本或回答质量优于固定模型。 |
| [Firstmate 任务分派](../cases/2026-09-18-firstmate/README.md) | 同时处理执行环境和模型档位，贴近已有代理编排系统。 | 25 个任务与 Fable 决策一致只说明小样本一致性，并非任务结果正确率。 |
| [本地编码代理分工](../cases/2026-09-18-local-delegation/README.md) | 可把机械任务、复杂推理和长实现任务分开。 | 分类规则、回退及长期完成质量没有完整公开；确定性 hook 不等于决策无误。 |
| [Skillbox 技能选择](../cases/2026-09-18-skillbox/README.md) | 适合技能数量较多、代理频繁寻找工具的场景。 | 没有公开召回率；预览图来自更早的 Skillbox 介绍，不是 Jev 集成实测截图。 |
| [Coding Garden 工具助手](../cases/2026-09-18-coding-garden-assistant/README.md) | 把确定性工具结果接回对话界面，覆盖个人助手常见操作。 | 参数和工具选择仍可能出错；作者“无幻觉”的说法没有充分验证。 |
| [Eve 工具调用代理](../cases/2026-09-18-eve-tool-agent/README.md) | 适合已有工具代理的局部替换，无需重写整个系统。 | 作者称效果接近，但没有公布足够样本或统一质量评分；节省不等于全面替代 LLM。 |
| [ai-cli 终端决策入口](../cases/2026-09-18-ai-cli/README.md) | 可通过通用命令行接入多个代理，无需各写一套接口。 | 这是接入工具，不是自带任务完成能力的 agent；需核验参数及错误处理。 |
| [Hono JevRouter · 按请求含义分流](../cases/2026-09-18-hono-semantic-router/README.md) | 适合探索按请求意图提供不同响应，语义规则与普通 Hono 路由并存；相比模型路由，它选择的是 HTTP 处理函数，结果更容易检查。 | 作者明确这是实验，不能用作认证或授权边界。语义分流增加模型调用成本与延迟；请求内容会发给 Jev，默认仅遮盖指定敏感请求头，路由顺序与输入干扰都可能改变结果。 |
| [Codex Model Router · 每轮选择模型](../cases/2026-09-19-codex-model-router/README.md) | 比通用模型选择演示更具体地嵌入 Codex 工作流，公开策略和回退；用户报告也暴露了过度选强模型的问题。 | 作者仍在调提示，缓存收益和上下文影响未定；仓库回放节省数字不等于这个用户的实测节省。 |
| [Claude Code Mod · 模型与推理力度路由](../cases/2026-09-19-claude-code-jev-router/README.md) | 相对 Codex Model Router，本例直接接入 Claude Code 的 hooks，并区分主会话与子代理，方便检查缓存和回退策略。 | 尚无完整任务质量、缓存费用和节省对照；无 Jev 密钥时会回退到宿主分类器，此路径不能算 Jev 效果。 |
| [Astra-Ares · 按任务进展调节思考力度](../cases/2026-09-23-astra-ares/README.md) | 比任务开始时选一次模型更细，公开代码可检查切换条件与上下文边界。 | 早期预览，需要补丁 CLI；不是在一次生成中途改内部思考。验证文档明确未测工作负载省费与缓存命中率，不能保证普遍省一半。 |
| [OpenClaw · 给插件接上统一决策接口](../cases/2026-09-23-openclaw-decisions/README.md) | 统一插件接口，方便把判断接进现有工作流，不必全由聊天模型逐项发起。 | 官方限定于开发检出版本，配套 provider 包仍等待支持版本发布；语音开关、工具过滤、压缩和模型路由多属探索或提案，不能当已全部落地。 |
| [Jev Workflow Builder · 把判断连成工作流](../cases/2026-09-23-jev-workflow-builder/README.md) | 能预览运行和通过 REST 调用，适合试验多步客服分流。 | 缺密钥时源码明确返回 mock 关键词结果，不能把无密钥演示当 Jev 推理；未验证生产并发和可靠性。 |
| [AgentRun · 让重复工作逐渐变成固定流程](../cases/2026-09-23-agentrun/README.md) | 明确区分研究、判断和执行，可追踪哪些步骤节省了工作量。 | 对照来自作者的合规告警任务，未公开完整原始案例和独立审计；少查资料也可能漏证据，不能只看费用。 |
| [Monid · 给工具工作流加上批量判断](../cases/2026-09-23-monid-jev-tools/README.md) | 与只选模型的路由器不同，强调现成工具拿到数据后的批量处理。 | 2,000 是工具目录规模，不是已验证任务数；30 倍缺完整基线，视频的转写/视觉处理成本未知。 |
| [Prompt Box · 自动选模型、电脑和项目目录](../cases/2026-09-23-prompt-box-router/README.md) | 比只选模型的路由多了执行环境与项目定位。 | 机器目录候选如何提供、权限如何约束尚未披露；选对字段不代表任务一定完成。 |
| [Corent · 按任务费用设置不同路由门槛](../cases/2026-09-23-corent-router/README.md) | 比统一门槛路由更强调不同工作量的错误成本。 | 千余模型是平台规模，不是逐一验证过的路由效果；阈值校准、回退对象和误选损失未披露。 |

## 可观察流程与机制

任务文本与候选能力描述 → Jev 选择或评分 → 应用检查候选及约束 → 调用模型、技能或工具。

路由的价值在于减少“选谁来做”的开销，任务本身仍由被选中的执行器完成。Firstmate 的 25 个一致决策是小样本对照；Skillbox 缺少相关技能召回数据；确定性调用结构并不保证模型判断正确。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。
