# 上下文与记忆筛选：原理与对比

**简体中文** | [English](2026-09-18-memory.en.md)

首次整理：2026-09-18；各案例来源复查时间见详情。验证状态：**未复现**。

## 选择建议

工具调用压缩处理当前会话的历史；记忆检索筛选处理外部记忆的召回候选。两者都以减少输入为目标，适用位置不同。优先观察信息保留与任务质量，再比较 token 降幅。 Compact Adviser 选择“什么时候压缩”，已有压缩工具选择“压缩哪些内容”，记忆筛选选择“召回哪些材料”。三者位置不同，可组合，比较时需看后续任务质量。

## 可观察流程与机制

历史记录或记忆候选 + 当前任务 → Jev 相关性评分 → 程序筛选 → 构造后续模型上下文。

筛选保留原文与重新生成摘要的误差形态不同：前者可能漏掉将来需要的信息，后者可能改写错事实。94% token 降幅来自作者一次快速测试，不能作为默认压缩比例。 最新压缩插件资料显示：提供经过预算裁剪的对话上下文，但省略工具输出正文；其录屏动画不调用 API。压缩体积、后续任务质量、缓存重建和总费用应分别评估，新增使用报告与评论者质疑见原案例。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。

## 复现实验建议

在长任务中测试延迟需求、错误恢复、旧决策追溯和跨轮指代；同时记录召回率、完成质量、筛选开销与总 token，保留可恢复的原始记录。
