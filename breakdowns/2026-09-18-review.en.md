# Code quality and safety checks: how they work and compare

[简体中文](2026-09-18-review.md) | **English**

First compiled: 2026-09-18; see each case for its source-review date. Status: **not independently reproduced**.

## Choosing an approach

Compare the 14-check PR reviewer, jev-review and jev-rabbit for explicit risks and escalation, iterative scoring and natural-language team rules respectively. Codebase classification examines overall structure. Command safety, jailbreak screening and upload checks guard different actions and need separate false-negative evaluations. The ESLint experiment judges snippet compliance; OpenCode permissions decide whether a tool action is allowed, questioned or denied before execution. They check different things and are not substitutes. Comment scoring separates accuracy from usefulness for clearer interpretation than one overall score, but currently shows only two trivial examples. ESLint checks snippets against rules, while PR tools cover broader changes. Compare their task scope and evidence size separately. Script.it scores diffs before generating explanations, reducing workflow overhead but recalling only 75% of confirmed bugs in its author evaluation. Compare both reduced false positives and increased misses with exploratory review. Goal verification checks turn-level completion; jev-align refines criteria with human labels. Measure false stops/misses for the former and held-out generalization for the latter, rather than treating training scores as reliability.

| [jev-rabbit natural-language rules](../cases/2026-09-18-jev-rabbit/README.en.md) | Can express team conventions that are difficult to capture with types or lint rules. | The post says release is upcoming; availability is unconfirmed. Ambiguous rules can produce inconsistent reviews. |

| [fx auto mode safety classifier](../cases/2026-09-18-fx-safety/README.en.md) | A concrete execution gate for studying low-latency prescreening. | The full test set is not published; average accuracy alone is insufficient to authorize risky actions. |
| [Jailbreak prompt prescreen](../cases/2026-09-18-jailbreak-screen/README.en.md) | A low-cost classifier could be a first stage in a broader security workflow. | Explicitly an early attempt. Approaching 100% is an aspiration, not an achieved result. |
| [Document upload checker](../cases/2026-09-18-upload-check/README.en.md) | Places classification before a concrete business action, useful for studying sensitive-content screening. | The demo does not establish detection of all sensitive information and cannot replace organizational access rules. |
| [Code judgments from ESLint rule descriptions](../cases/2026-09-18-eslint-rule-judgments/README.en.md) | Explores turning written rules into quick code judgments. More focused than general PR scoring and suitable for comparison with deterministic lint results. | The roughly 90% correctness claim concerns the author’s snippet experiment, not whole repositories or real PRs. Public samples, independent evaluation and per-rule false positives/negatives are still needed. It provides no deterministic-linter guarantee. |
| [OpenCode intent-aware permissions](../cases/2026-09-18-opencode-intent-permissions/README.en.md) | Expresses a shared semantic restriction across shell, webfetch and other tools without enumerating every command. Goes beyond risk scoring by participating in permission decisions. | The video does not establish bypass resistance; deterministic hard boundaries remain necessary. Version 0.1.0 explicitly excludes Code Mode execute and sends policies, recent user messages and tool inputs to TypeSafe. No adversarial or permission tests were run here. |
| [Code comments: accuracy and usefulness scores](../cases/2026-09-18-code-comment-scoring/README.en.md) | Separating factual correctness from informational value makes issues easier to interpret than a single overall code score. Like the ESLint experiment, it examines local code, but evaluates comment quality rather than rule compliance. | Two trivial examples do not establish performance on complex code. Scores are not independently measured test accuracy, and automatic comment deletion or rewriting is not demonstrated. The author describes a possible gate for reducing larger-model review, not a complete reviewer. |
| [Script.it: flag issues before writing review comments](../cases/2026-09-19-script-code-review/README.en.md) | Explicitly separates detection from explanation compared with agent-led review, and discloses the recall tradeoff. | The private set’s size and labels are unavailable. | [jev-align: refine decision criteria with human feedback](../cases/2026-09-20-jev-align/README.en.md) | Adds feedback, diff inspection and rollback to manual prompting, supporting binary, multiclass, multilabel and ordered-score tasks. | Training gains do not guarantee generalization. Held-out evaluation is optional; annotation, reflection and repeated evaluation costs must also be counted. |

## Workflow and mechanism

Code or proposed action plus explicit rules → several narrow judgments → combine in code → notify, block or escalate.

The PR reviewer publishes an uncertainty-escalation rule, making it easier to inspect than an overall score. jev-review feedback can guide iterations, but a high score is not a passing test suite. Cheap screening does not remove the need to assess error costs.

Individual input and implementation differences are documented in the linked cases. This is an application-level synthesis, not a claim that every implementation is identical or an account of Jev’s internal training architecture.

## Suggested reproduction experiments

Measure false positives and negatives by risk type against independently labeled data. Test insufficient evidence, adversarial instructions, conflicting rules and uncertain results. Retain human review and static-tool baselines.
