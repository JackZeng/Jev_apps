# Code quality and safety checks: how they work and compare

[简体中文](2026-09-18-review.md) | **English**

Collected / source-reviewed: 2026-09-18. Status: **not independently reproduced**.

## Choosing an approach

Compare the 14-check PR reviewer, jev-review and jev-rabbit for explicit risks and escalation, iterative scoring and natural-language team rules respectively. Codebase classification examines overall structure. Command safety, jailbreak screening and upload checks guard different actions and need separate false-negative evaluations.

## Individual comparisons

These are analytical strengths and limitations based on public descriptions, not controlled experimental findings.

| Example | Strengths / suitable uses | Limitations / missing evidence |
| --- | --- | --- |
| [jev-review MCP](../cases/2026-09-18-jev-review/README.en.md) | Fits into the development loop and supports before/after comparisons. | An experimental plugin. Optimizing a score can reward gaming the metric; it does not replace tests or human review. |
| [14-check PR risk review](../cases/2026-09-18-typed-pr-review/README.en.md) | Explicit checks and escalation rules are easier to inspect than a single overall code-quality score. | Only six PRs are shown; semantic risk classification does not establish comprehensive vulnerability detection. |
| [jev-rabbit natural-language rules](../cases/2026-09-18-jev-rabbit/README.en.md) | Can express team conventions that are difficult to capture with types or lint rules. | The post says release is upcoming; availability is unconfirmed. Ambiguous rules can produce inconsistent reviews. |
| [Codebase complexity classifier](../cases/2026-09-18-codebase-classifier/README.en.md) | Evaluates code structure and may complement line-level PR checks. | Overengineering depends on project context; classification has not been shown to guide safe refactoring. |
| [fx auto mode safety classifier](../cases/2026-09-18-fx-safety/README.en.md) | A concrete execution gate for studying low-latency prescreening. | The full test set is not published; average accuracy alone is insufficient to authorize risky actions. |
| [Jailbreak prompt prescreen](../cases/2026-09-18-jailbreak-screen/README.en.md) | A low-cost classifier could be a first stage in a broader security workflow. | Explicitly an early attempt. Approaching 100% is an aspiration, not an achieved result. |
| [Document upload checker](../cases/2026-09-18-upload-check/README.en.md) | Places classification before a concrete business action, useful for studying sensitive-content screening. | The demo does not establish detection of all sensitive information and cannot replace organizational access rules. |

## Workflow and mechanism

Code or proposed action plus explicit rules → several narrow judgments → combine in code → notify, block or escalate.

The PR reviewer publishes an uncertainty-escalation rule, making it easier to inspect than an overall score. jev-review feedback can guide iterations, but a high score is not a passing test suite. Cheap screening does not remove the need to assess error costs.

Individual input and implementation differences are documented in the linked cases. This is an application-level synthesis, not a claim that every implementation is identical or an account of Jev’s internal training architecture.

## Suggested reproduction experiments

Measure false positives and negatives by risk type against independently labeled data. Test insufficient evidence, adversarial instructions, conflicting rules and uncertain results. Retain human review and static-tool baselines.
