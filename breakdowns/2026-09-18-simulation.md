# NPC、驾驶与群体模拟：原理与对比

**简体中文** | [English](2026-09-18-simulation.en.md)

收录 / 更新 / 来源复查：2026-09-18。验证状态：**未复现**。

## 选择建议

NPC 需求选择适合研究角色行为，500 agents 演示关注并发吞吐。驾驶原型中，不暂停的模拟器更明确暴露延迟约束；无人机原型有代码线索。小镇与虚构 personas 属于叙事和构思工具，不能据合成人物反应预测真实世界。

## 同类逐项对比

以下优势和限制是基于作者公开说明的技术分析；不构成同条件实验结论。

| 案例 | 相对优势 / 适用场景 | 限制 / 尚缺证据 |
| --- | --- | --- |
| [按需求行动的 NPC](../cases/2026-09-18-npc-needs/README.md) | 可用语义描述扩展 NPC 行为，接近 utility AI / smart objects 场景。 | 需求权重、冲突和长期行为一致性未说明；传统规则可能更简单便宜。 |
| [500 个 3D agents](../cases/2026-09-18-npc-500/README.md) | 关注群体规模和吞吐，适合研究模拟环境负载。 | 35 次调用/秒不等于每个 agent 每秒 35 次；没有逐角色更新频率。 |
| [“FSD”驾驶模拟演示](../cases/2026-09-18-driving-toy/README.md) | 直观展示快速决策接入驾驶模拟的可能性。 | 不是 Tesla FSD 复现或实车验证，无法支持道路安全和自动驾驶能力结论。 |
| [不暂停的实时驾驶模拟](../cases/2026-09-18-realtime-driving/README.md) | 明确关注决策延迟与运动状态过时的问题，比暂停仿真更接近实时约束。 | 仍是模拟器；未给道路覆盖、事故率或长时稳定性数据。 |

| [Unstable Government 小镇](../cases/2026-09-18-unstable-government/README.md) | 生成叙事与居民选择分工明确，适合互动故事。 | 角色反应是虚构模拟，不能作为社会政策影响预测。 |
| [150 位虚构用户意向](../cases/2026-09-18-synthetic-personas/README.md) | 快速检查人物设定与产品叙述之间的匹配，可用于构思访谈问题。 | 合成意见不是实际用户调查，不能当成市场需求验证。 |

## 可观察流程与机制

模拟状态与角色目标 → Jev 决策 → 仿真执行 → 更新状态；叙事场景可由 LLM 提供候选反应。

驾驶视频中的“FSD”是原作者命名，不是对 Tesla 产品或实车能力的复现认定。群体演示的总 API 吞吐必须与单角色更新频率分开。虚构用户的采用意向不能代替实际访谈或实验。 无人机仓库明确了 MuJoCo 仿真与高频控制/低频模型决策的分层，并主动披露了单次成功对照的限制。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。

## 复现实验建议

公开环境、状态更新频率、暂停策略、网络抖动及失败定义；长期统计碰撞、任务成功和单角色行为一致性。合成用户实验应再与真实调查结果对照。
