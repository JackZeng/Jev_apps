# 浏览器与电脑操作：原理与对比

**简体中文** | [English](2026-09-18-browser.en.md)

首次整理：2026-09-18；各案例来源复查时间见详情。验证状态：**未复现**。

## 选择建议

要研究浏览器循环，优先看 Browser Use 与 Stagehand：前者明确 DOM 动态动作空间及文本回退，后者明确无障碍树和执行器分工。桌面应用可看 CoreML/OCR，Cua 当前公开预览可用于研究受约束的语义动作执行；需要长任务上下文则看 agent-desktop。语音入口和 QA 演示解决的是交互或验收问题，不宜只按速度排名。 Runlayer 强调多会话并行探索，仍缺路径覆盖和缺陷检出证据；Sac 的日历对照聚焦单个桌面任务，后续已公开无障碍树文字候选与执行器分工；“最快”仍缺统一基准。两者都不能仅凭操作视频代替验收断言。 Tester Army 侧重 Web / 移动端框架，尚未核实开源发布；ego lite 聚焦商品筛选，混合模型的效果不能归给 Jev 一项。Browser Use 新增 WebMCP 同源对照，需区分任务覆盖和每次尝试成功率。 Third Hand 通过提取指令中的现成文字支持输入，TipTour 的 Jev 模式只做点击，Ultrafast 则可请小型 LLM 填字。三者的输入能力不同，不能只按“无需 LLM”或单步延迟排名。 arc-cua 与 Third Hand 按同作者相关方案合并：前者接收外部规划器给定的字面值，后者从请求提取候选文字。都应以完整任务完成率衡量，不能把减少大型模型调用说成不再观测界面。

## 同类逐项对比

以下优势和限制是基于作者公开说明的技术分析；不构成同条件实验结论。

| --- | --- | --- |
| [Browser Use · Ultrafast](../cases/2026-09-18-browser-use/README.md) | 动作集合随页面更新，公开了代码，适合研究完整浏览器执行循环。 | 仍有 LLM 文本生成；当前 MVP 不覆盖 shadow DOM、iframe、canvas、上传等；少量同任务重复不代表通用跨网站可靠性。 |
| [Stagehand 浏览器控制](../cases/2026-09-18-stagehand/README.md) | 输入和执行器分工明确，适合已有 Stagehand 项目。 | 依赖页面无障碍信息；没有公布同一任务集上的成功率。 |
| [Cua · jev-use](../cases/2026-09-18-cua-jev-use/README.md) | 动作候选由本地程序掌控并验证，有 Python/TypeScript 预览和独立结果检查。 | 不是已发布的桌面视觉操控功能；当前预览不含截图感知，也不代表 Windows/Linux 原生桌面能力已认证。 |
| [TipTour · CoreML + OCR 桌面点击](../cases/2026-09-18-coreml-ocr/README.md) | 无需 DOM，可检查原生 Mac 点击循环；与 Third Hand 相比专注点击，Gemini 语音/输入是单独模式。 | 检测错误会影响点击；Jev 模式按排名选目标，没有目标置信度截断，不支持自由写作。Gemini 模式可发送音频和截图，因此“图片留本机”不能扩展到所有模式。 |
| [OpenCode + agent-desktop](../cases/2026-09-18-agent-desktop/README.md) | 把长期上下文管理与快速动作选择分开。 | 仍依赖 LLM；原帖未说明快照编码方式，不能推断 Jev 原生看图。 |
| [Kernel 浏览器演示](../cases/2026-09-18-kernel-browser/README.md) | 有在线入口，便于进一步复现交互体验。 | 只有短演示；未说明复杂页面、失败恢复和任务完成率。 |
| [语音控制浏览器](../cases/2026-09-18-voice-browser/README.md) | 减少手动操作，适合明确而短的语音指令。 | 转写、页面定位与浏览器执行都另有成本；决策延迟不等于端到端延迟。 |
| [OpenCode 应用测试](../cases/2026-09-18-opencode-qa/README.md) | 展示了自动化操作用于开发验收的方向。 | 操作速度不能证明断言正确或覆盖充分；目前按演示收录。 |
| [Runlayer · 并行浏览器对抗测试](../cases/2026-09-18-runlayer-adversarial-testing/README.md) | 重点是同时探索多条操作路径，可与已有 OpenCode 应用测试对照并发探索和开发后验收的差异。作者补充了具体工具组合，便于追查实现。 | 窗口多不等于路径覆盖广；并发数、真实缺陷检出率、重试和完整运行成本未说明。“几分钱”是作者概述，不能换算成每次测试的成本保证。 |
| [Sac · Codex + Jev 操作 Mac 日历](../cases/2026-09-18-sac-calendar-computer-use/README.md) | 同一个明确任务的并排演示便于观察操作停顿，补充了现有浏览器和 OCR 案例之外的桌面流程探索。 | 一次日历演示不足以确定平均加速、成功率或总成本。开源代码增加了可检查性，但最新“Codex 里最快”的说法缺统一任务基准；本库未运行该工具。 |
| [ego lite · Amazon 商品筛选](../cases/2026-09-19-ego-product-decisions/README.md) | 与通用网页操作相比，它演示一个明确的商品筛选任务，便于按选中结果比较。 | 评分依据、重复次数与完整费用未公开；20 个决策和界面 10/10 结果是不同口径，不代表 20 次完整购物或下单。 |
| [Tester Army · Web / 手机端测试演示](../cases/2026-09-19-tester-army-e2e/README.md) | 与 Runlayer 的并发探索同属测试工具，但强调跨 Web / 手机的测试框架，适合比较支持平台和断言设计。 | 演示不能证明稳定检出缺陷；作者称即将提供，未核实可运行的开源发布，不能写成已可安装产品。 |
| [Third Hand / arc-cua · 选动作操作 Mac](../cases/2026-09-20-third-hand/README.md) | Third Hand 从请求提取文字，无需额外生成模型；arc-cua 接收上游规划器给定的字面值，便于接入其他代理。两者均把选动作与本地执行分开。 | 两个仓库不是同一程序；为避免同作者相关桌面方案拆卡，归一条介绍。arc-cua 仍逐步观测并调用 Jev；不能认定“解决了电脑操作”，无标签图形和完整任务成功率仍是缺口。 |

## 可观察流程与机制

观测页面或桌面 → 构建可执行动作候选 → Jev 选动作 → 执行器操作 → 重新观测。

DOM、无障碍树与 OCR 是不同观测接口。CoreML/OCR 方案的“像素留在本地”不等于内容全在本地；Browser Use 的文字输入回退也说明需要生成的环节仍可能交给 LLM。以上架构分别来自作者陈述，其余集成未披露的编码方式保持未知。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。

## 复现实验建议

用同一组只读任务比较完成率、步骤数、总耗时、全流程费用与失败恢复；覆盖无标签按钮、动态页面、弹窗及桌面窗口变化。不要拿单步推理耗时与整个任务耗时相比。

**尚未执行实验。** 当前没有本仓库产生的耗时、准确率或成本结果。
