# 实时交互与组合实验：原理与对比

收录 / 更新 / 来源复查：2026-09-18。验证状态：**未复现**。

## 选择建议

TypeGPU 案例把本地感知与远端语义判断结合；Ask Jev 提供简单判断界面；词表和字符聊天展示选择循环；像素绘图与 RISC-jeV 展示将大量小判断组合成输出。这些适合作为机制启发，不应直接当成替代专用模型或程序的产品。

## 同类逐项对比

以下优势和限制是基于作者公开说明的技术分析；不构成同条件实验结论。

| 案例 | 相对优势 / 适用场景 | 限制 / 尚缺证据 |
| --- | --- | --- |
| [TypeGPU 实时语义特效](../cases/2026-09-18-typegpu-realtime/README.md) | 将本地感知与语义决策分离，适合实时交互媒体。 | 整个流水线不只包含 Jev；没有端到端延迟和各模块消融结果。 |
| [Ask Jev](../cases/2026-09-18-ask-jev/README.md) | 有公开体验入口，直观认识判断模型的输出形式。 | 娱乐和产品交互示例，不能将任意判断当成可靠知识回答。 |
| [有限词表聊天](../cases/2026-09-18-word-chat/README.md) | 展示如何用选择能力组合出生成式交互。 | 词表限制表达；每词一次决策的耗时与成本不适合直接类比文本模型。 |
| [29 选项字符生成](../cases/2026-09-18-character-chat/README.md) | 控制循环明确，比有限词表更自由。 | 字符循环调用次数大；不证明模型原生具备文本生成 API。 |
| [并行像素绘图](../cases/2026-09-18-pixel-drawing/README.md) | 把分类输出组合成视觉结果，具有原理探索价值。 | 不是已验证的通用图像生成器；品质、分辨率和总成本未知。 |
| [RISC-jeV 逻辑门实验](../cases/2026-09-18-riscv/README.md) | 提供明确的组合层次，适合理解“决策如何构成计算”。 | 概念实验，不是计算效率优势；确定性代码完成逻辑运算更合适。 |

## 可观察流程与机制

准备有限候选或原子问题 → Jev 判定 → 程序组合结果 → 更新交互状态或输出。

词表聊天与字符聊天都由程序把单步选择拼接成文本；这不改变 API 的判断式输出性质。RISC-jeV 中逻辑门和指令解释层叠加，展示可组合性，不意味着用模型算逻辑门更高效。

各案例的输入和实现差异见上表链接的来源记录。该流程是应用层归纳，不代表每个项目都采用完全相同的实现，也不是对 Jev 内部训练架构的推断。

## 复现实验建议

记录候选规模、分辨率或字符数、循环次数和全程费用；与确定性代码或专用生成模型比较输出质量。感知流水线需分开测本地模型、网络决策及渲染延迟。
