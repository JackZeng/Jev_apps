## 用人话解释原理

像一份懂意思的历史菜单：程序先列出过去的命令，Jev 挑最像你想输入的一条。候选、匹配和是否显示由程序控制，用户接受建议后才进入命令行。

## 应用场景与价值

输入半条命令或一句意图，从用过的命令里推荐下一条。

**可借鉴点（分析）**：比字面前缀补全更能处理描述意图的输入，又将结果限制在历史候选里；与预测性启动器一样做候选选择，但对象是命令而非文件。

## 输入、操作与输出

固定版本 README 说明：zsh 插件读取最近 100 条不同历史命令，有前缀匹配时先缩小候选；单一前缀候选无需模型调用。其余用 Choice 选命令 ID、Noul 判断是否有合适候选，按门槛显示建议，并丢弃输入已改变的旧结果。

没有披露的提示词、状态格式、阈值或失败恢复逻辑保持未知。应用按作者演示收录，不认定已稳定上线。

## 原理拆解与同类比较

历史命令可能过时或带敏感内容，并会作为候选发给服务端。选择正确不代表执行安全；仍需用户检查。README 报告请求约 0.7–0.9 秒，不能套用其他演示的毫秒宣传。作者明确是实验，不是其日常使用证明。

同类逐项对比、公共流程和建议实验见 [专题分析](../../breakdowns/2026-09-18-interaction.md)。实现说明来自作者公开材料；优势及尚缺证据属于本仓库分析，不能视为模型内部架构已被证实。
