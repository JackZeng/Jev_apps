## 用人话解释原理

普通路由像看门牌号分信件，这个实验还读信件表达的意思。开发者用文字描述各个处理入口，Jev 逐项判断是否适合，程序按注册顺序选中第一个达标入口。

## 应用场景与价值

根据请求像是来自人还是 AI，选择返回网页或 Markdown 等不同内容。

**可借鉴点（分析）**：适合探索按请求意图提供不同响应，语义规则与普通 Hono 路由并存；相比模型路由，它选择的是 HTTP 处理函数，结果更容易检查。

## 输入、操作与输出

固定版本代码把方法、URL、请求头和截断后的文本正文组成状态，一次请求为每条路由提出 Noul 是非问题。选择首个概率达到阈值的已注册路由，默认阈值 0.5；不是选择最高分。普通路径路由可先返回，无匹配时走未找到处理。

没有披露的提示词、状态格式、阈值或失败恢复逻辑保持未知。应用按作者演示收录，不认定已稳定上线。

## 原理拆解与同类比较

作者明确这是实验，不能用作认证或授权边界。语义分流增加模型调用成本与延迟；请求内容会发给 Jev，默认仅遮盖指定敏感请求头，路由顺序与输入干扰都可能改变结果。
